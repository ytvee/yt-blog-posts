**Opening (контекст проекта):**
- "Мы пишем онлайн-компилятор для отладки ИИ-сервисов"
- "Статья — это скорее приглашение к обсуждению"

**Problem statement (описание ошибки):**
- Название: "Проблема"
- Описание: пишем экземпляры класса UserFile в Redux
- Ошибка в консоли: "A non-serializable value"
- Screenshot ошибки

**The why (философия Redux):**
- Подзаголовок: "Основная цель Redux"
- Объяснение: состояние должно быть предсказуемым
- Три причины, почему сериализация важна:
  1. Time-travel debugging
  2. Регидратация и SSR
  3. Практический риск (потеря функций класса)

**Quick fix (что НЕ делать):**
- Подзаголовок: "Отключение проверки сериализации"
- Показывает middleware с `serializableCheck: false`
- Объяснение: да, можно отключить, но это не лучший путь

**The solution (практический подход):**
- Подзаголовок: "Решение кейса"
- Введение: что именно сериализуем и как

**Code examples (подробно):**
1. Интерфейс сериализованного файла (IUserFileSerializable)
2. Методы класса UserFile:
   - fromSerializable() — из сериализованных данных в объект
   - toSerializable() — из объекта в сериализованный формат
3. Методы FilesService:
   - toSerializableFiles() — сериализация массива
   - fromSerializableFiles() — десериализация массива
4. Redux slice с reducers
5. Использование в компонентах (useState + FilesService)
6. Мутация файлов (dispatch + toSerializable)

**Conclusion (и приглашение):**
- Объяснение подхода: гибкость + сохранение возможности работать с полноценными объектами
- Приглашение к обсуждению: "делитесь опытом в комментариях"
