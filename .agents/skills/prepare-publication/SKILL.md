# Подготовить публикацию

1. Убедиться, что пользователь явно утвердил текущую версию статьи.
2. Использовать lowercase kebab-case slug рабочего каталога как имя файла и часть URL.
3. Проверить:

```powershell
node scripts/validate-project.mjs work/articles/<slug>/current.md
node scripts/publication-gate.mjs check --slug <slug>
```

4. Скопировать утверждённый черновик только командой:

```powershell
node scripts/prepare-publication.mjs --slug <slug> --approved-by user
```

5. Сообщить путь `content/<slug>.md` и подтверждение совпадения SHA-256.

Не менять `published: false`. Не удалять и не изменять рабочий каталог, ревизии, медиаплан и отчёт обучения. Повторный запуск с тем же содержимым должен быть успешным; новую утверждённую версию разрешено записать в тот же slug-файл только после повторного прохождения шлюза.

Не читать никакие файлы из `content/` как референсы, источники тем, материал для проверки пересечений или редакционного обучения. Допустимы только технические операции записи и проверки хэша конкретного целевого файла.
