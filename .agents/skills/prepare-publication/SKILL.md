# Подготовить публикацию

1. Убедиться, что пользователь явно утвердил текущую версию статьи.
2. Использовать lowercase kebab-case slug рабочего каталога как имя файла и часть URL.
3. Проверить:

```powershell
node scripts/validate-project.mjs work/articles/<slug>/current.md
node scripts/publication-gate.mjs check --slug <slug>
```

4. Скопировать утверждённый черновик только командой:

```powershell
node scripts/prepare-publication.mjs --slug <slug> --approved-by user
```

5. Проверить вывод скрипта: совпадение SHA-256 и удаление только `work/articles/<slug>/`. При ошибке удаления сообщить, что копирование завершено, но очистка не завершена; не удалять другие каталоги.
6. Выполнить `npm.cmd run build:drafts`. Проверить отсутствие опубликованного slug в списке и `_site/drafts/`. После следующего успешного деплоя Pages проверить исчезновение публичной страницы по `../../../knowledge/draft-preview.md`.
7. Сообщить путь `content/<slug>.md`, SHA-256 и результат очистки. Не ссылаться на удалённый `current.md` как на доступный файл.

Не менять `published: false`. После успешного копирования и проверки SHA-256 скрипт удаляет рабочий каталог этой статьи вместе с ревизиями, брифом, медиапланом и отчётом обучения. Поэтому `learn-from-article` обязательно завершить до запуска публикации. При отсутствии рабочей папки и наличии `content/<slug>.md` повторный запуск ничего не меняет. Новую утверждённую версию из заново подготовленной рабочей папки разрешено записать в тот же slug-файл только после повторного прохождения шлюза.

Не читать никакие файлы из `content/` как референсы, источники тем, материал для проверки пересечений или редакционного обучения. Допустимы только технические операции записи и проверки хэша конкретного целевого файла.
