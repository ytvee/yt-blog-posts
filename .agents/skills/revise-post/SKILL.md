# Исправить статью

## Загрузить контекст

Обязательно прочитать:

- `../../../knowledge/author-style.md`;
- `../../../knowledge/editorial-policy.md`;
- `../../../knowledge/blog-format.md`;
- `../../../work/articles/<slug>/brief.md`;
- `../../../work/articles/<slug>/current.md`.

Не перечитывать примеры, если правка не требует заново калибровать стиль.

## Зафиксировать итерацию

1. Определить статью по пути пользователя или единственному подходящему каталогу. При нескольких равноправных вариантах уточнить путь.
2. Найти максимальный номер в `revisions/` и выбрать следующий трёхзначный номер `<NNN>`, начиная с `001`.
3. Если любой файл с выбранным номером уже существует, не перезаписывать его, а выбрать следующий свободный номер.
4. До изменения скопировать актуальный `current.md` в `revisions/<NNN>-before.md`.
5. Проверить, что `<NNN>-before.md` идентичен `current.md` на момент начала правки. Это предпоследняя версия статьи для текущего круга.
6. Сохранить исходный текст или очищенную расшифровку правки в `revisions/<NNN>-feedback.md`. Не пересказывать отзыв так, чтобы изменился его смысл.

## Применить правки

- Менять только запрошенные фрагменты и необходимые для связности соседние места.
- Сохранять факты, даты, числа, имена, цитаты, личные истории и позицию автора.
- Не заменять конкретную историю общим рассуждением.
- Не исправлять спорный факт молча: проверить его или вынести вопрос отдельно.
- При конфликте новой правки со старым правилом выполнять новую правку и передать конфликт в `learn-from-edits`.
- При неоднозначности выбирать вариант, который меньше меняет исходный смысл.

После редактирования:

1. Записать отредактированный текст в `current.md`.
2. Пересчитать `readingTime`:

```powershell
node scripts/reading-time.mjs work/articles/<slug>/current.md --write
```

3. После пересчёта сохранить полный `current.md` в `revisions/<NNN>-after.md`. Это последняя версия статьи для текущего круга.
4. Проверить, что `current.md` и `<NNN>-after.md` идентичны.
5. Не изменять, не перезаписывать и не удалять старые `000-initial.md`, `<NNN>-before.md` и `<NNN>-after.md`. В новом круге создать следующую пару снимков.
6. Считать прежние `media-plan.md` и `learning-report.md` неактуальными: их SHA статьи больше не должен проходить шлюз.
7. Проверить файл:

```powershell
node scripts/validate-project.mjs work/articles/<slug>/current.md
```

8. Использовать `learn-from-edits` для анализа пары `<NNN>-before.md` / `<NNN>-after.md` и отзыва, если пользователь явно не попросил ничего не запоминать.
9. Перед апрувом заново подготовить медиаплан.
10. Выполнить `npm.cmd run build:drafts` по `../../../knowledge/draft-preview.md`. Публичная страница обновится после push и успешного деплоя. Проверить деплой перед сообщением об обновлённой ссылке.

Правила сохранения ревизий действуют до публикации. После успешного `prepare-publication` рабочая папка этой статьи удаляется целиком.

В ответе кратко перечислить применённые изменения, путь к актуальной версии и неразрешённые вопросы. Не выдавать полный текст статьи повторно, если пользователь этого не просил.
