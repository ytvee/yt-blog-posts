# Спланировать изображения

1. Прочитать `../../../knowledge/blog-format.md`, `references/editorial-ink-prompts.md`, `../../../templates/media-plan.md` и статью.
2. Всегда спланировать две самостоятельные композиции с одной ассоциацией:
   - горизонтальную hero-иллюстрацию `16:9` внутри статьи;
   - квадратную OG-картинку `1:1` только в медиаплане.
3. Не получать OG квадратным кропом hero. Сохранить идею и ключевые объекты, но заново собрать композицию под центр квадратного кадра.
4. Добавлять другие изображения только там, где они помогают понять переход, механизм, эмоциональный поворот или длинный блок. Не ставить картинку после каждого заголовка.
5. Для каждого изображения внутри статьи вставить:

```html
<!-- IMAGE_SLOT id="img-01" role="hero" ratio="16:9" alt="..." association="..." -->
```

6. Использовать `ratio="16:9"` для ролей `hero`, `section`, `evidence` и `diagram`. Для `video` ratio не обязателен.
7. Заполнить `media-plan.md` по шаблону:
   - поставить `schemaVersion: 2`, актуальный SHA статьи и `status: ready`;
   - перенести в `slots` те же `id`, `role`, `ratio`, `alt` и `association`, что стоят в статье;
   - заполнить `ogImage` с `ratio: "1:1"`, `linkedSlotId` горизонтальной hero и той же `association`;
   - хранить полные промпты в Markdown-разделах под контрактом.
8. Для каждой генерируемой иллюстрации сразу написать полный промпт по локальному справочнику. Не ждать отдельного запроса пользователя.
9. Для скриншотов, видео и других доказательных материалов не писать генеративный промпт. Вместо него зафиксировать подготовку к `16:9`: сохранить все данные, подписи, оси, даты и фильтры; не растягивать и не обрезать значимые элементы; при необходимости добавить свободные поля.
10. После вставки заглушек пересчитать `readingTime`, затем вычислить SHA итогового `current.md` и записать его в медиаплан. Не менять статью после фиксации SHA.
11. Выполнить `npm.cmd run build:drafts` по `../../../knowledge/draft-preview.md`: изменение `current.md` должно попасть в следующую сборку предпросмотра.

Cloudinary URL пользователь подставляет позднее. Не придумывать URL и не загружать изображения автоматически.
