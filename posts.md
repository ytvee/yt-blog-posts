# Инструкция Для Агента-Писателя: Posts

Используй этот документ, когда создаешь или редактируешь `post` в content-репозитории.

## Обязательный Frontmatter Contract

Добавляй в каждый `post` только валидный YAML frontmatter.

Обязательные поля:

- `title: string`
- `date: YYYY-MM-DD`
- `description: string`
- `readingTime: integer > 0`
- `published: boolean`

Допустимые опциональные поля:

- `tags: string[]`
- `seoTitle: string`
- `ogImage: string`
- `locale: string`
- `updatedAt: YYYY-MM-DD`
- `slug: string`
- `adBanners: { imageSrc: string; alt: string; href?: string }[]`

Не добавляй другие ключи frontmatter. Если human-readable правила и runtime-схема приложения-рендерера расходятся, доверяй runtime-схеме и content loader.

## Правила Файла И Slug

- Создавай файл только как `content/<slug>.md`.
- Используй только один markdown-файл на один материал.
- Держи `slug` в имени файла, а не во frontmatter.
- Используй только `kebab-case` в имени файла.
- Не создавай вложенные папки внутри `content/`.
- Не меняй slug опубликованного поста без явной необходимости.
- Не превышай размер одного markdown-файла больше `5 MiB`.

## Правила Полей

### `title`

- Пиши человеческий заголовок для страницы.
- Не используй технические заглушки, черновые пометки и placeholder-текст.

### `date`

- Пиши дату публикации в формате `YYYY-MM-DD`.
- Не используй относительные даты, текстовые месяцы и нестабильные форматы.

### `description`

- Пиши `description` как реальный лид и SEO-summary.
- Давай читателю ясное обещание содержания поста.
- Держи формулировку конкретной и пригодной для карточки, metadata и вводного абзаца.
- Не пиши технические описания вроде `Draft`, `TBD`, `Описание поста` или внутренние заметки редактора.

### `readingTime`

- Ставь только целое число больше нуля.
- Пересчитывай `readingTime` после заметных изменений тела текста.
- Не оставляй приблизительные или заведомо неверные значения.

### `published`

- Используй `published: true` только для готового материала.
- Используй `published: false` для draft-версии.
- Не считай draft опубликованным текстом.

### `updatedAt`

- Добавляй `updatedAt`, если после публикации материал заметно изменился.
- Используй тот же формат `YYYY-MM-DD`.
- Не добавляй `updatedAt`, если правка несущественная.

### `ogImage`

- Считай `ogImage` практически обязательным для опубликованного поста.
- Используй app-owned путь `/images/...`, внешний URL или relative asset path вроде `../media/cover.webp`.
- Не оставляй опубликованный пост без `ogImage`, если нет жесткой причины.

### `adBanners`

- Используй `adBanners` только если баннеры действительно нужны этому посту.
- Соблюдай точную структуру: `{ imageSrc, alt, href? }[]`.
- Заполняй `alt` осмысленно.
- Не добавляй произвольные поля внутрь баннера.

## Правила Body

- Не используй markdown-заголовок `#` в теле текста.
- Помни, что page-level `<h1>` уже берется из `title`.
- Начинай структуру с `##` или с обычного абзаца.
- Пиши body как чистый публикационный текст, а не как служебную заметку.
- Используй markdown-изображения только там, где они реально помогают материалу.
- Для body images используй только допустимые пути: `/images/...`, внешний URL или relative asset path вроде `../media/...`.
- Пиши осмысленный alt text для каждого изображения.

## Разрешено

- Добавлять подзаголовки уровня `##` и ниже.
- Добавлять inline-изображения в теле поста.
- Использовать ссылки, списки, цитаты и обычный markdown, если они работают на текст.
- Использовать `tags`, если они помогают навигации и не выглядят случайным набором слов.

## Запрещено

- Использовать `#` в body.
- Оставлять placeholder values в `title`, `description`, ссылках, картинках и frontmatter.
- Оставлять пустые code fences.
- Оставлять комментарии для редактора, служебные TODO, JSON-вставки, отладочные блоки и технический мусор.
- Добавлять произвольные frontmatter keys.
- Смешивать в одном файле несколько материалов.
- Использовать невалидные даты и нечисловой `readingTime`.

## Шаблон

```md
---
title: 'Заголовок поста'
date: '2026-04-22'
description: 'Короткий и конкретный лид, который работает как summary и поисковый сниппет.'
tags: ['тема', 'контекст']
readingTime: 4
published: false
ogImage: '../media/cover.webp'
seoTitle: 'Заголовок поста для поисковой выдачи'
locale: 'ru-RU'
updatedAt: '2026-04-22'
adBanners:
    - imageSrc: '../media/banner.webp'
      alt: 'Краткое описание баннера'
      href: 'https://example.com'
---

## Первый подзаголовок

Открой пост сильным первым абзацем без служебных пояснений и без повторения frontmatter.

![Осмысленный alt text](../media/cover.webp)

## Второй подзаголовок

Продолжай текст как готовую публикацию.
```

## Pre-Publish Checklist

- Проверь, что файл лежит в `content/` и имя файла в `kebab-case`.
- Проверь, что frontmatter валиден и не содержит лишних ключей.
- Проверь, что обязательные поля заполнены.
- Проверь, что `date` и `updatedAt` записаны в `YYYY-MM-DD`.
- Проверь, что `readingTime` пересчитан и больше нуля.
- Проверь, что `description` работает как лид и summary.
- Проверь, что в body нет `#`.
- Проверь, что все изображения и ссылки реальны, а не placeholders.
- Проверь, что `ogImage` задан для опубликованного поста.
- Проверь, что в файле нет пустых блоков, служебных комментариев и технического мусора.
