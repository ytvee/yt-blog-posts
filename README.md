# YT Blog Posts

Репозиторий подготовки и хранения русскоязычных статей `ytdev.me`: от авторского брифа и исследования источников до сохранения утверждённого черновика в `content/`.

## Рабочий процесс

Каждая статья хранится в `work/articles/<latin-kebab-slug>/`.

1. Подготовить тему, факты и личный опыт в `brief.md`.
2. При необходимости проверить актуальность темы через `trend-research`.
3. Создать `current.md` и пройти редакторский цикл с полной историей в `revisions/`.
4. Перед утверждением подготовить медиаплан.
5. После явного утверждения провести обучение на принятой статье.
6. Скопировать утверждённый черновик в `content/<slug>.md` через скрипт публикации; после проверки хэша скрипт удалит рабочую папку этой статьи.

Любое изменение `current.md` делает прежний медиаплан и отчёт обучения устаревшими. Готовность определяется по SHA-256 статьи.

## Публикация

После явного утверждения команда

```powershell
node scripts/prepare-publication.mjs --slug <slug> --approved-by user
```

проверяет статью, медиаплан и отчёт обучения, затем копирует `work/articles/<slug>/current.md` в `content/<slug>.md`. Флаг `published` остаётся `false`. После проверки совпадения SHA-256 удаляется только рабочая папка этой статьи вместе с историей ревизий. Остальные черновики сохраняются. Повторный запуск при уже удалённой папке и существующем целевом файле ничего не меняет. Новая утверждённая версия из заново подготовленной рабочей папки обновляет тот же файл после повторных проверок.

`content/` — только выход публикационного процесса. Посты из него нельзя использовать как источники тем, текста, стиля, проверки пересечений или редакционного обучения.

После ручного push в `main` workflow `.github/workflows/redeploy-blog.yml` уведомляет репозиторий сайта об изменениях.

## Публичные черновики

После создания, правки или публикации статьи выполнять `npm.cmd run build:drafts`. Команда создаёт `_site/index.html` со списком и `_site/drafts/<slug>/index.html` для каждого `work/articles/<slug>/current.md`. Статьи отображаются колонкой до 600 пикселей. HTML не хранится в Git и не редактируется вручную.

Workflow `.github/workflows/deploy-drafts.yml` после push в `main` или ручного запуска публикует только `_site/` на GitHub Pages. В Settings → Pages должен быть выбран источник **GitHub Actions**. Фактический URL доступен в окружении `github-pages` после успешного деплоя. Локальная сборка сама по себе не обновляет публичные страницы.

Правила, поддерживаемые медиа и примеры жизненного цикла: [публичные черновики](knowledge/draft-preview.md).

## Проверки

Требуется Node.js 24. В PowerShell используйте `npm.cmd`:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run validate
npm.cmd run build:drafts
node scripts/validate-project.mjs work/articles/<slug>/current.md
node scripts/publication-gate.mjs check --slug <slug>
```

Для HTML используется `markdown-it`; версия и транзитивные зависимости зафиксированы в `package-lock.json`. `.env` не нужен.

## Каталоги

| Каталог | Назначение |
|---|---|
| `.agents/skills/` | Навыки редакционного процесса |
| `knowledge/` | Политики, стиль автора и формат блога |
| `memory/` | Подтверждённые редакторские закономерности |
| `examples/` | Разрешённые стилевые примеры |
| `templates/` | Шаблоны рабочих файлов |
| `work/articles/` | Единственное место редактирования статей |
| `content/` | Утверждённые черновики для сайта; не источник референсов |
| `scripts/` | Проверки и локальная публикация |
| `_site/` | Генерируемые страницы GitHub Pages; исключены из Git |
