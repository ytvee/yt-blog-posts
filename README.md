# YT Blog Posts

Репозиторий подготовки и хранения русскоязычных статей `ytdev.me`: от авторского брифа и исследования источников до сохранения утверждённого черновика в `content/`.

## Рабочий процесс

Каждая статья хранится в `work/articles/<latin-kebab-slug>/`.

1. Подготовить тему, факты и личный опыт в `brief.md`.
2. При необходимости проверить актуальность темы через `trend-research`.
3. Создать `current.md` и пройти редакторский цикл с полной историей в `revisions/`.
4. Перед утверждением подготовить медиаплан.
5. После явного утверждения провести обучение на принятой статье.
6. Скопировать утверждённый черновик в `content/<slug>.md`.

Любое изменение `current.md` делает прежний медиаплан и отчёт обучения устаревшими. Готовность определяется по SHA-256 статьи.

## Публикация

После явного утверждения команда

```powershell
node scripts/prepare-publication.mjs --slug <slug> --approved-by user
```

проверяет статью, медиаплан и отчёт обучения, затем копирует `work/articles/<slug>/current.md` в `content/<slug>.md`. Флаг `published` остаётся `false`, а рабочий каталог и история ревизий сохраняются. Повторный запуск без изменений идемпотентен; новая утверждённая версия обновляет тот же файл.

`content/` — только выход публикационного процесса. Посты из него нельзя использовать как источники тем, текста, стиля, проверки пересечений или редакционного обучения.

После ручного push в `main` workflow `.github/workflows/redeploy-blog.yml` уведомляет репозиторий сайта об изменениях.

## Проверки

Требуется Node.js 24. В PowerShell используйте `npm.cmd`:

```powershell
npm.cmd test
npm.cmd run validate
node scripts/validate-project.mjs work/articles/<slug>/current.md
node scripts/publication-gate.mjs check --slug <slug>
```

Внешние npm-зависимости и `.env` не нужны.

## Каталоги

| Каталог | Назначение |
|---|---|
| `.agents/skills/` | Навыки редакционного процесса |
| `knowledge/` | Политики, стиль автора и формат блога |
| `memory/` | Подтверждённые редакторские закономерности |
| `examples/` | Разрешённые стилевые примеры |
| `templates/` | Шаблоны рабочих файлов |
| `work/articles/` | Единственное место редактирования статей |
| `content/` | Утверждённые черновики для сайта; не источник референсов |
| `scripts/` | Проверки и локальная публикация |
