# YT Writer

Локальный конвейер для подготовки русскоязычных статей `ytdev.me`: от авторского брифа и исследования источников до доставки утверждённого черновика в `ytvee/yt-blog-posts`.

## Что умеет проект

- ищет актуальные темы в Hacker News;
- хранит бриф, текущую версию и историю правок;
- проверяет формат статьи, медиаплан и готовность к публикации;
- учится на утверждённых статьях и принятых правках;
- после явного утверждения ставит черновик в очередь;
- через GitHub Actions переносит его в репозиторий постов.

## Требования

- Node.js 24;
- Git;
- Codex с локальными навыками из `.agents/skills`;
- для публикации — право записи в `ytvee/yt-blog-posts`.

Внешние npm-зависимости и файл `.env` не нужны.

## Первый запуск

```powershell
npm.cmd test
```

## Рабочий процесс статьи

Каждая статья хранится в `work/articles/<latin-kebab-slug>/`.

1. Подготовить тему, заметки, факты и личный опыт в `brief.md`.
2. При необходимости проверить актуальность темы через `trend-research`.
3. Создать `current.md` и пройти редакторский цикл.
4. Перед утверждением подготовить медиаплан.
5. После явного утверждения провести обучение на принятой статье.
6. Создать очередь публикации.

Любое изменение `current.md` делает прежний медиаплан и отчёт обучения устаревшими. Готовность проверяется по SHA-256 статьи.

## Проверки

```powershell
npm.cmd test
npm.cmd run validate
node scripts/validate-project.mjs work/articles/<slug>/current.md
```

В PowerShell используется `npm.cmd`, потому что системная политика Windows может запрещать запуск обёртки `npm.ps1`. В обычном терминале или CI те же команды можно выполнять через `npm`.

## Публикация

После явного утверждения проект создаёт каталог `publication/queue/<english-slug>/`. Пользователь вручную коммитит и отправляет изменения в `main`.

GitHub Action проверяет очередь, переносит материал в `ytvee/yt-blog-posts`, а после успешной доставки удаляет рабочую очередь и каталог статьи. В Actions должен быть настроен секрет `YT_BLOG_POSTS_TOKEN` с правом записи в целевой репозиторий.

Если workflow завершился ошибкой, не удаляйте очередь вручную. Исправьте причину и перезапустите задачу: доставка рассчитана на повторный запуск и проверяет конфликты.

## Основные каталоги

| Каталог | Назначение |
|---|---|
| `.agents/skills/` | Навыки редакторского конвейера |
| `knowledge/` | Политики, стиль автора и формат блога |
| `memory/` | Подтверждённые редакторские закономерности |
| `scripts/` | Проверки и публикация |
| `templates/` | Шаблоны рабочих файлов |
| `work/articles/` | Статьи в работе |
| `publication/queue/` | Только утверждённые материалы |
