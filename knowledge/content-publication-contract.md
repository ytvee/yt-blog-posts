# Контракт публикации в `content/`

- Единственный источник редактирования: `work/articles/<slug>/current.md`.
- Целевой файл: `content/<slug>.md`, где slug соответствует имени рабочего каталога.
- URL статьи: `https://www.ytdev.me/blog/<slug>`.
- Фронтматтер должен точно соответствовать `knowledge/blog-format.md`.
- При копировании сохранять `published: false`.
- Перед копированием обязательны валидная статья, готовый медиаплан, готовый отчёт обучения и явный апрув пользователя.
- После копирования SHA-256 исходного и целевого файлов должен совпадать.
- Повторный запуск с тем же содержимым успешен; новая утверждённая версия заменяет файл того же slug.
- После проверки совпадения SHA-256 скрипт удаляет только рабочий каталог опубликованного slug, включая ревизии, бриф, медиаплан и отчёт обучения. До публикации история сохраняется.
- Перед удалением проверять путь и отсутствие символических ссылок. При несовпадении хэшей или ошибке копирования рабочую папку не удалять.
- Если копирование завершено, а удаление не удалось, сообщать оба результата отдельно. Перед удалением сохраняется техническая квитанция `work/.publication-cleanup/<slug>.json` с хэшем опубликованного файла и снимком состава рабочей папки. Повторный запуск сверяет квитанцию, целевой файл и оставшиеся рабочие файлы, затем завершает очистку; новые или изменённые файлы блокируют удаление. После успеха квитанция удаляется. При отсутствии рабочей папки, квитанции и наличии целевого файла повторный запуск ничего не меняет.
- После публикации выполнять `npm.cmd run build:drafts`. Публичная страница исчезает после следующего успешного деплоя Pages.

`content/` является только выходом публикационного процесса. Его файлы запрещено читать для поиска тем, проверки пересечений, обучения, редакционной памяти и калибровки стиля.
