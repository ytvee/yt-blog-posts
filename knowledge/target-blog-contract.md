# Контракт `ytvee/yt-blog-posts`

- Целевой репозиторий: `ytvee/yt-blog-posts`.
- Ветка: `main`.
- Один файл на статью: `content/<english-kebab-slug>.md`.
- Заголовок H1 находится во фронтматтере; `#` в теле запрещён.
- До первого `##` разрешены обложка, `IMAGE_SLOT`, лид и авторское вступление — так устроены существующие статьи.
- Рабочая доставка всегда содержит `published: false`.
- `IMAGE_SLOT` допустим только в черновике; перед `published: true` его заменяют Cloudinary URL либо удаляют.
- `readingTime`: читаемые символы / 1500 + 0,2 минуты за изображение; округление вверх при дробной части от 0,3; минимум 1.

Локальный workflow валидирует этот контракт. Репозиторий назначения остаётся источником истины; если его правила изменятся, обновить этот файл и валидатор отдельной принятой правкой.

## Доступ GitHub Action

- В `ytvee/yt-writer` создать repository secret `YT_BLOG_POSTS_TOKEN`.
- Значение — fine-grained PAT с доступом только к `ytvee/yt-blog-posts` и разрешением `Contents: write`.
- Workflow использует встроенный `GITHUB_TOKEN` с `contents: write` только для коммита очистки в `ytvee/yt-writer`.
- Не записывать PAT в `.env`, manifest, логи или файлы репозитория.
